How it works

  • Five candidate models were compared on a validation split, and the best by PR-AUC was registered in MLflow. The test split was scored once, for the numbers above.
  • The decision threshold is not 0.5. It follows from stated costs for a missed fraud and a false alarm, with a cap on the false alarm rate, all set in the project configuration.
  • Each answer comes with SHAP contributions, computed by the service for that one payment.
  • V1 to V28 are anonymised principal components that the bank released instead of the raw card data, so they have no business meaning that can be read off.
  • The service validates every field, logs each prediction, and compares recent inputs with the training data for drift, reported at /metrics.
  • It runs on Google Cloud Run, which stops the container when nobody is using it. If this page was slow to open, a new container was starting.
Data: Credit Card Fraud Detection, Machine Learning Group, Université Libre de Bruxelles, under the Open Database License. The transactions on this page are rows from its test split.
